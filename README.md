## What's Built

### Browsing & Discovery
- **Home page** — auto-advancing hero banner (top 5 trending) + 4 horizontal rails: Trending Today, Popular Movies, Popular TV, Upcoming Movies
- **Movie detail pages** (`/movie/[id]`) — backdrop hero, poster, genres, runtime, rating, tagline, overview, trailer modal (YouTube embed), top 10 cast strip, Similar & Recommended rails
- **TV show detail pages** (`/tv/[id]`) — same as movie but shows seasons/episodes count
- **Genre pages** (`/genres/[id]`) — paginated discover grid, toggle between Movies and TV

### Search
- **`/search`** — debounced real-time search across all movies & TV shows, results update as you type

### Auth
- **Sign in / Sign up** via Clerk (Google, email/password) — modal-based, no page redirect
- Protected routes: `/profile` and `/favorites` require sign-in

### User Features (requires sign-in)
- **Favorites** (`/favorites`) — save any movie or TV show, remove from favorites grid
- **Reviews** — write a 1–10 star review + text on any detail page, delete your own reviews
- **Profile** (`/profile`) — avatar, favorite/review counts, reviews tab, AI Picks tab

### AI Recommendations (multi-rail engine)

The profile's **AI Picks** tab runs four independent recommendation rails in parallel, each with its own loading state, retry button, and 24-hour cache.

#### Rail 1 — "Because you loved [Title]"
- Anchors on the user's highest-rated favorite (ties broken by most-recently added)
- 4 picks generated by Claude Haiku with the anchor as context
- Rail title updates to `"Because you loved Whiplash"` once the anchor is known

#### Rail 2 — "More from your top genres"
- 4 picks from Claude Haiku weighted by the user's top 5 genres and rating bias

#### Rail 3 — "Hidden gems" (no LLM)
- Queries TMDb `/discover` directly with the user's top 2 genres, `vote_count ≤ 2000`, `vote_average ≥ 6.5`, sorted by rating
- Movie/TV split mirrors the user's `mediaSplit` ratio (e.g. 70% movies → 3 movies + 1 TV)
- No Claude call — faster, cheaper, and actually uses real vote counts

#### Rail 4 — "Try something different"
- 4 picks from Claude Haiku explicitly outside the user's top genres
- Hidden entirely if the user has fewer than 3 identifiable top genres

#### Taste profile (`lib/taste.ts`)
Built from the user's Convex data on every request:
- **topGenres** — top 5 genre IDs by weighted frequency (favorite = 1.0, review = `rating/10`); deterministic tiebreaker: score DESC → count DESC → id ASC
- **ratingBias** — `"harsh"` (avg < 6), `"balanced"` (6–8), `"generous"` (> 8)
- **mediaSplit** — ratio of movies to TV across all favorites + reviews
- **recentSignals**, **lovedExamples** (rated ≥ 9), **dislikedExamples** (rated ≤ 4) — all fed into the Claude prompt

#### Direct deep-links (no more "Find it →")
Claude returns `{ title, year, mediaType }`. The server runs a TMDb title+year search immediately after each pick to resolve a real `tmdbId` and `posterPath`. Cards link directly to `/movie/[tmdbId]` or `/tv/[tmdbId]`. If a title can't be found on TMDb, it is dropped and Claude is re-prompted (max 2 retries per rail).

#### Feedback loop (👍 / 👎)
- Each pick card has thumbs-up / thumbs-down buttons
- 👎 invalidates the rail that contained the pick — next load regenerates it
- Last 20 👎 titles passed as `avoidTitles` in future prompts
- Last 20 👍 titles added to `lovedExamples` in future prompts

#### Caching & race safety
- Picks are persisted in Convex with a 24-hour TTL per user + section
- Race-safe writes: a generation started before a 👎 invalidation cannot overwrite a newer cached result (compared via `generatedAt` timestamp)
- `?force=1` on any rail (or "Refresh all" button) bypasses the cache

#### Empty state
If the user has fewer than 3 favorites, the AI Picks tab shows a CTA — no API calls are made.

### Infrastructure
- **Convex** real-time database for users, reviews, favorites, recommendation cache, and feedback
- **Clerk webhook** syncs new users into Convex; `UserSync` component as client-side fallback
- **TMDb health check** — `GET /api/health/tmdb` verifies the token is working

## Local Setup

### 1. Clone and install
```bash
git clone https://github.com/shwetashekhar98/Popcorn-Magic.git
cd Popcorn-Magic
npm install
```

### 2. Get your API keys

| Service | Where | What you need |
|---|---|---|
| TMDb | https://developer.themoviedb.org | v4 Read Access Token (long JWT) |
| Convex | https://dashboard.convex.dev | Auto-configured via `npx convex dev` |
| Clerk | https://dashboard.clerk.com | Publishable key + Secret key |
| Anthropic | https://console.anthropic.com | API key |

### 3. Configure environment variables

Fill in `.env.local`:
```env
TMDB_READ_ACCESS_TOKEN=eyJhbGci...

NEXT_PUBLIC_CONVEX_URL=https://xxx.convex.cloud
CONVEX_DEPLOYMENT=prod:xxx

NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_...
CLERK_SECRET_KEY=sk_test_...
CLERK_WEBHOOK_SECRET=whsec_...   # optional for local dev

ANTHROPIC_API_KEY=sk-ant-...
```

### 4. Start Convex + Next.js (two terminals)

**Terminal 1:**
```bash
npx convex dev
```

**Terminal 2:**
```bash
npm run dev
```

Open http://localhost:3000

### 5. Verify setup
```
GET http://localhost:3000/api/health/tmdb
→ { "ok": true, "count": 20 }
```

## API Reference

### `GET /api/recommendations`

Generates or returns cached picks for one recommendation rail.

| Param | Values | Description |
|---|---|---|
| `section` | `becauseYouLoved` \| `topGenres` \| `hiddenGems` \| `different` | Which rail to fetch |
| `force` | `1` | Bypass 24-hour cache and regenerate |

**Responses:**
- `200` — `{ section, anchorTitle?, picks: RailPick[], cached: boolean }`
- `204` — Rail 4 hidden (user has < 3 identifiable top genres)
- `401` — Not authenticated
- `404` — Convex user not found

```ts
interface RailPick {
  tmdbId: number;
  mediaType: "movie" | "tv";
  title: string;
  year: string;
  posterPath: string | null;
  reason: string;  // ≤ 120 chars, references specific taste signals
}
```

## Deploying to Vercel

### Required environment variables

| Variable | Description |
|---|---|
| `TMDB_READ_ACCESS_TOKEN` | TMDb v4 read access token |
| `NEXT_PUBLIC_CONVEX_URL` | Production Convex URL from `npx convex deploy` |
| `CONVEX_DEPLOYMENT` | Production deployment name |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk publishable key |
| `CLERK_SECRET_KEY` | Clerk secret key |
| `CLERK_WEBHOOK_SECRET` | Clerk webhook signing secret |
| `ANTHROPIC_API_KEY` | Anthropic API key |

### Clerk webhook (for user sync)
1. Clerk Dashboard → **Webhooks → Add Endpoint**
2. URL: `https://<your-domain>/api/webhooks/clerk`
3. Events: `user.created`, `user.updated`
4. Copy Signing Secret → `CLERK_WEBHOOK_SECRET`

### Deploy Convex to production
```bash
npx convex deploy
```
Copy the output URLs into Vercel env vars.
